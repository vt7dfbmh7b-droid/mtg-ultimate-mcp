# V0.9 Multi-Source Evidence Model

V0.9 makes cross-referencing a first-class part of MTG Ultimate. The goal is not to produce one mysterious aggregate power score. It is to answer different questions with the sources that are actually suited to those questions, then explain agreement or disagreement in plain English.

## Source classes

### Rules and exact card facts
- Wizards of the Coast: official rules, product, ban/restriction and release information.
- Scryfall: Oracle identity, color identity, Commander legality, exact set/collector printing identity, finishes and reference prices.
- Commander Spellbook: curated Commander combo and near-combo evidence.

These sources carry the most weight for factual rules/card/printing claims. Community deck usage cannot override them.

### Competitive Commander evidence
- TopDeck.gg: existing structured tournament-results/decklist integration when configured.
- EDHTop16: V0.9 structured tournament/meta cross-reference using its documented API shape.
- cEDH Decklist Database: curated archetypes and primers used as strategy context, not as a tournament ranking or tier list.

TopDeck and EDHTop16 can contain overlapping underlying events. Their agreement is useful corroboration but must not be counted as two fully independent samples of the same event.

### Recorded paper-game evidence
- Playgroup.gg: public paper Commander game/deck statistics and outcomes as a real-game context source.

Tracked games are self-selected and playgroup composition matters, so these signals should not be treated as a universal population win rate.

### Broad Commander/community construction
- EDHREC: adoption, synergy, themes and broad Commander trends.
- Archidekt: existing public-deck integration with attribution and deck-structure comparisons.
- Moxfield: public lists and detailed primers as reference material.
- MTGGoldfish: Commander decklists, metagame browsing and price-history context.
- AetherHub: additional public decklists, deck-building tools and simulations.

Frequency means a card is commonly used. It does not prove that the card is optimal for a particular commander, budget, bracket, meta or player goal.

### Independent deck-analysis tools
- DeckCheck: CRISPI / PowerTune / DeckTrim style analysis as a second opinion.

The plugin should compare DeckCheck-style conclusions with rules, simulation, tournament/community evidence and the deck's actual intended plan rather than optimizing solely for one proprietary score.

### Pricing and availability
- Scryfall: exact printing identity plus reference price fields.
- TCGfind NZ: New Zealand availability/local-price cross-check destination.
- MTGGoldfish, TCGplayer and Cardmarket: secondary international market references.

A price comparison is valid only after the desired physical printing is identified. A cheaper unrelated printing cannot bypass a Final Fantasy/Marvel/Secret Lair/foil/etc. printing restriction.

## New MCP tools

### `list_reference_sources_v09`
Returns the available source catalog, evidence class, intended use, relative weighting and source-specific cautions.

### `research_commander_across_sources_v09`
Creates a Commander research packet for one or two commanders. It can pull EDHTop16 structured evidence and returns attributed research destinations for the wider source set.

### `cross_reference_deck_evidence_v09`
Combines the existing Archidekt and TopDeck integrations with EDHTop16 plus the broader research/source registry. This is intended to be called after or alongside deck analysis, upgrades and from-scratch builds.

## Build and upgrade workflow

For an upgrade:

1. Enforce Commander rules and the requested printing policy.
2. Analyse the deck's structure, game plan, combos and simulated consistency.
3. Generate candidate cuts/additions.
4. Cross-reference the candidates and overall architecture against suitable evidence classes.
5. Prefer changes supported by multiple independent kinds of evidence when they also improve the deck's actual plan.
6. Rebuild the full deck, validate it again and compare before/after simulation.
7. Return exact IN -> OUT swaps and qualifying physical printings.

For a deck from scratch, use the same evidence after the first legal draft and during later optimization passes. A popular card should not displace a commander-specific synergy merely because it has a high inclusion rate.

## User-facing output

The internal evidence can be complex. Normal answers should remain short and practical, for example:

- `This card is common in community builds and also appears in successful competitive lists; the simulation improves early interaction.`
- `This is popular on EDHREC, but tournament/reference lists rarely use it and it is slow in this deck, so I would not add it here.`
- `This swap looks mechanically good, but the exact Final Fantasy printing is over the requested budget.`

Raw source counts, URLs and detailed metrics should be shown only when useful or requested.

## Reliability rules

- Rules/legality cannot be decided by popularity.
- One tournament result does not prove causation.
- EDHREC/public-list frequency is an adoption signal, not a win-rate signal.
- Curated lists/primers provide strategy context, not measured outcomes.
- Recorded casual games and cEDH tournament results represent different environments and should not be blended blindly.
- Multiple sites may ingest or reference the same underlying deck/event; avoid double-counting where overlap is known or plausible.
- Do not depend on undocumented private APIs. Where no stable documented integration is available, provide an attributed research destination rather than a brittle scraper.
- Always preserve exact printing restrictions and local-price context when the user asks for them.
