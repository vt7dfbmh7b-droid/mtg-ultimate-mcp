# V0.15 Historical Card-Data Source Inventory

_Audit/current-state date: 2026-08-20 NZST_

This document records the provenance-safe card-data contract used by the experimental V0.15 learning/evidence path. It does **not** promote V0.15, change `server-current`, or claim that a current provider feed is a retrospective historical archive.

## Safety rule

Historical predictor features may use Oracle/card/printing facts only when the exact source contents are independently shown to have been available by the requested predictor cutoff.

An old card release date is not proof that today's API/file contents were historically available. Current files can contain later Oracle text, legality changes, printings, metadata, or corrections. Current truth must never be silently backdated.

## Source policy

The machine-readable inventory is `src/services/historical-carddata-source-inventory-v15.ts`.

Current policy:

- Scryfall `default_cards`: authoritative current structured source; forward capture supported; retrospective rich-feature backfill blocked unless an independently verified historical snapshot exists.
- MTGJSON `AllPrintings`: useful current/daily-build source and possible independent structured source; native adapter still differs from the Scryfall-shaped promotion feature pipeline; current files are not retrospective proof.
- No current provider is silently treated as a historical archive.

## Scryfall current bulk contract

Live verification on 2026-08-20 established the current provider contract from Scryfall itself.

Discovery endpoint:

`https://api.scryfall.com/bulk-data`

The required `default_cards` record exposes current metadata including its ID/type/update time, compressed size, API metadata URI, and an HTTPS `*.scryfall.io` `jsonl_download_uri` ending in `.jsonl.gz`.

The pipeline therefore treats the current physical-printing bulk source as **gzip-compressed JSON Lines**, not as an assumed JSON array.

Fail-closed discovery/capture behavior includes:

- exactly one `default_cards` manifest record;
- bounded provider request with descriptive User-Agent / explicit JSON Accept header;
- no conversion of provider `updated_at` into historical-availability proof;
- HTTPS `*.scryfall.io` static-file origin and `.jsonl.gz` path enforcement;
- manifest compressed-size enforcement;
- SHA-256 over the exact compressed provider bytes before decompression;
- rejection of ambiguous HTTP content encoding that could alter exact source bytes;
- bounded compressed input and separately bounded gzip output;
- per-record JSONL/UTF-8/card-shape validation;
- capture observation time assigned when the source is actually observed, never backdated.

Dedicated live control:

- `.github/workflows/scryfall-carddata-source-live.yml`
- `scripts/live-scryfall-carddata-source-v15.ts`

The live control checks the current manifest contract without persisting the bulk card dataset or card names in its public audit.

## Retained forward snapshots — implemented

The retained Scryfall path is no longer future work.

`.github/workflows/scryfall-carddata-retention-v15.yml` can capture the exact current `default_cards` `.jsonl.gz` bytes, validate them, and persist them using immutable/content-addressed storage semantics.

Retention outputs are separated by purpose:

- exact compressed raw bytes → GHCR package `mtg-ultimate-mcp-carddata`;
- provenance manifest → GHCR package `mtg-ultimate-mcp-carddata-manifests`;
- compact public audit → hashes/metadata/reference information only.

The raw content SHA-256 binds the exact source bytes. The manifest records observation/provenance and the immutable raw artifact reference. Later replay verifies retained bytes against the manifest before the snapshot can be used as predictor truth.

A retained capture becomes useful historical evidence **only from its real observation time forward**. It cannot prove what Scryfall contained before that capture.

## Pinned historical replay

`src/services/historical-carddata-acquisition-v15.ts` also supports a separately audited pinned archived snapshot contract.

A valid archive pin requires exact source identity/URI, content hash, archive version, effective/publication timing, supported format, and optional byte-length identity. Temporal provenance is assessed **before** network use. Exact received bytes are bounded and hashed before they may feed historical feature extraction.

No production retrospective archive is currently registered merely because this adapter exists.

## MTGJSON

MTGJSON publishes maintained current downloadable data, build metadata, and validation hashes. Those properties are useful for integrity and possible future source diversity, but they do not establish a replayable historical daily archive for arbitrary past predictor cutoffs.

Until a separately replayable historical path is verified, current MTGJSON data remains current-only for retrospective predictor provenance.

## Predictor integration

Verified historical/retained card data feeds the existing provenanced deck-feature path, which also preserves:

- exact deck/printing resolution;
- date-bounded printing existence;
- dated Commander construction/eligibility validation;
- predictor provenance separate from tournament outcome provenance;
- training-only normalization fit.

The promotion-grade projection is intentionally frozen at the current milestone to:

- `manaEfficiency`;
- `interactionEfficiency`.

That experiment is scoped to strict TopDeck event-top-cut prediction. It is **not** evidence of universal Commander deck strength. Any future expansion of the promotion feature set must be precommitted before observing the future holdout it will evaluate.

## Historical archive research results

Two negative-availability investigations must not be overstated:

- The bounded Scryfall/Wayback probe found no usable archived bulk-manifest captures through the tested July 1–August 20, 2026 route.
- That result means **unavailable through the tested route**, not “no historical Scryfall archive exists anywhere.”

Likewise, provider unavailability is never converted into evidence of absence.
