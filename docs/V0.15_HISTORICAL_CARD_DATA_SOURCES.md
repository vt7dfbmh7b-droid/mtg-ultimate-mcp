# V0.15 Historical Card-Data Source Inventory

Audit date: 2026-08-20

This document records the source decision and acquisition contract for provenance-safe historical predictor/card data. It does **not** promote V0.15, change `server-current`, or establish that a current feed is a retrospective historical archive.

## Safety requirement

Historical predictor features may use Oracle text, type line, mana value, printing identity, release date and Commander legality only when the exact source contents are independently shown to have been available by the requested feature cutoff.

A source is not historical merely because individual cards have old release dates. A file fetched today may contain later Oracle text, legality changes, new printings or other future knowledge.

## Source policy

The machine-readable policy is `src/services/historical-carddata-source-inventory-v15.ts`.

Current inventory:

- Scryfall `default_cards`: current authoritative bulk source, forward capture enabled, retrospective rich-feature backfill blocked, `historicalArchiveVerified: false`.
- MTGJSON `AllPrintings`: current daily build candidate, native adapter still required for this pipeline, retrospective rich-feature backfill blocked, `historicalArchiveVerified: false`.

No current provider is silently promoted to a historical archive.

## Scryfall current bulk contract — live verified 2026-08-20

Primary discovery endpoint:

- `https://api.scryfall.com/bulk-data`

The provider contract was discovered from Scryfall itself and then encoded fail-closed. The current `default_cards` entry exposes:

- `id`;
- `type = default_cards`;
- `updated_at`;
- provider metadata `uri` on `api.scryfall.com/bulk-data/...`;
- positive `compressed_size`;
- `jsonl_download_uri` pointing to an HTTPS `*.scryfall.io` static file ending in `.jsonl.gz`.

The current bulk payload is therefore treated as **gzip-compressed JSON Lines**, not as the older JSON-array/download-URI shape.

Discovery rules:

- exactly one `default_cards` entry is required;
- malformed, missing or duplicate entries fail closed;
- discovery uses a descriptive User-Agent and explicit JSON Accept header;
- discovery has a bounded timeout and no automatic retry loop;
- `updated_at` is current-provider metadata only and is never converted into historical availability proof.

Dedicated live control:

- `.github/workflows/scryfall-carddata-source-live.yml`
- `scripts/live-scryfall-carddata-source-v15.ts`

The live control performs one bounded manifest request. It validates provider shape and source policy but deliberately does **not** download the large bulk card file or persist card names, card data or the static download path in its audit artifact.

## MTGJSON current source

Verified current properties from MTGJSON documentation include:

- public API data is rebuilt daily;
- `Meta.json` exposes build date/version metadata;
- downloadable v5 files have SHA-256 validation sidecars;
- `AllPrintings` contains printing-level card data.

Historical decision:

- the documented current file service is not, by itself, a replayable historical archive;
- sparse software/release tags are not equivalent to daily historical card-data snapshots;
- provider hashes improve integrity checking but do not authorize backdating current contents;
- MTGJSON remains `candidate-adapter-required` for forward capture because its native schema differs from the existing feature pipeline.

## Implemented acquisition contract

### 1. Pinned archived snapshot replay

`src/services/historical-carddata-acquisition-v15.ts` provides `acquirePinnedHistoricalCardDataV15` for a separately audited archive pin containing:

- source ID;
- exact source URI;
- SHA-256 content hash;
- archive version;
- snapshot effective time;
- archive publication time;
- supported data format;
- optional exact byte length.

Before network access, the existing historical provenance assessment must accept the archive publication/effective times for the requested feature cutoff. The source is bounded while bytes stream, including when `Content-Length` is missing; exact bytes are hashed and optional exact byte length is enforced before the data can feed historical feature extraction.

An archive pin is **not** permission to invent publication metadata. No production retrospective archive is registered by this milestone.

### 2. Generic forward contemporaneous capture

The generic acquisition layer can capture current Scryfall-shaped data with a timestamp assigned at observation time and a local SHA-256 over the exact received bytes.

The existing provenance gate rejects any requested feature cutoff earlier than the capture time. Current data can therefore become future evidence without being backdated into earlier TopDeck outcomes.

### 3. Scryfall gzip JSON Lines forward capture

`src/services/scryfall-forward-carddata-capture-v15.ts` implements the current source-specific path.

Hard safeguards:

- source URI must be HTTPS, hosted on `*.scryfall.io`, and end in `.jsonl.gz`;
- source policy must still permit forward capture and must still report `historicalArchiveVerified: false`;
- the manifest's `compressed_size` is enforced as the expected source-file byte length;
- compressed bytes are bounded while streaming;
- provenance SHA-256 covers the **exact compressed source bytes** before decompression;
- HTTP transport `Content-Encoding` is rejected when it could make exact provider-file bytes ambiguous through automatic transport decoding;
- gzip decompression has a separate decoded-byte bound using Node's `maxOutputLength`;
- JSON Lines records are parsed individually with strict UTF-8, JSON and required Scryfall-card-shape validation;
- a per-record byte limit prevents a single malformed line from consuming unbounded memory;
- observation/retrieval time is assigned at capture and cannot be moved backward by provider `updated_at` metadata.

Captured current Scryfall data can feed the existing provenanced feature extractor only for a cutoff at or after its real capture time.

## Predictor integration

Verified pinned archive acquisition feeds `extractProvenancedDeckFeatureSnapshotV15`, preserving:

- historical printing resolution;
- date-bounded printing existence;
- dated Commander eligibility/construction validation;
- predictor provenance separate from target/outcome provenance.

The current 4,395 TopDeck deck/outcome candidates across 173 accepted events are **not** made retrospectively trainable by this milestone. Without a verified predictor snapshot available by each historical cutoff, those rows remain unavailable for rich historical features rather than receiving current card truth.

## Deterministic and live validation

The milestone has deterministic coverage for:

- archive cutoff rejection before network access;
- exact SHA-256 and byte-length verification;
- streaming source-size guards;
- malformed UTF-8/JSON/card data;
- source-policy retrospective blocking;
- forward-capture backdating rejection;
- Scryfall origin and `.jsonl.gz` enforcement;
- manifest-shape failures and duplicate/missing `default_cards`;
- exact compressed-size enforcement;
- bounded gzip expansion;
- invalid gzip and invalid JSON Lines;
- transport-encoding ambiguity rejection;
- end-to-end discovery plus forward capture with one observation timestamp.

A dedicated live Scryfall manifest control verifies the current provider contract without persisting the bulk card dataset.

## Next source work

1. Add a **retained forward capture/content-addressed snapshot persistence** layer for exact `.jsonl.gz` bytes plus discovery metadata, observation time and SHA-256.
2. Make retained snapshot identity immutable/replayable so later historical evaluation can prove what was actually observed at each capture time.
3. Define retention/index/lookup semantics and explicit unavailable coverage when no capture existed by a requested cutoff.
4. Continue searching for a genuine independently replayable historical archive; never weaken the provenance gate if none exists.
5. Once trusted historical or forward-retained predictor snapshots overlap real TopDeck candidates, measure usable/rejected/unavailable coverage before fitting a model.

V0.15 remains experimental and shadow-only. Stable promotion remains an explicit later user decision.
