# V0.15 External Oracle Benchmark Strategy

Ultimate MTG should not become confident merely because its own tests agree with its own assumptions. V0.15 therefore adds an external-oracle benchmark layer that compares normalized Ultimate MTG behavior against independent open MTG projects where those projects are strongest.

The goal is not to outsource truth or copy another implementation. The goal is differential testing: same scenario, pinned inputs/version/seed where possible, normalized outputs, then investigate every meaningful disagreement.

## Initial external references

### j4th/mtg-mcp-server

- License: MIT
- Use: independent MCP/deck-workflow/rules/Commander-analysis comparison target.
- Strength: broad MTG MCP surface and many user-facing deck workflows.
- Policy: implementation patterns may be studied under the applicable license/notice requirements, but Ultimate MTG still needs independent tests and design justification.

### nccurry/mtg-mcp

- License: AGPL-3.0-or-later
- Use: architecture/evidence/statistics benchmark by default.
- Strength: evidence provenance, exact probability calculations, deterministic offline testing, revision safety, provider pacing, reproducibility, and strong coverage discipline.
- Policy: treat as behavioral/architecture reference by default. Do not silently copy AGPL implementation into Ultimate MTG core.

### Card-Forge/forge

- License: GPL-3.0
- Use: external rules/simulation oracle.
- Strength: mature MTG rules engine, broad mechanic/card coverage, Commander-capable gameplay.
- Policy: prefer pinned external process/snapshot parity rather than embedding Forge source into Ultimate MTG core.

### witchesofthehill/manabrew

- License: AGPL-3.0-or-later, with Forge-derived GPL components.
- Use: parity-harness methodology reference and secondary Forge-family comparison target.
- Strength: same decks + same seed + deterministic choices + trace comparison + first mismatch reporting.
- Important lineage rule: Manabrew explicitly uses Forge as its reference. Forge and Manabrew therefore count as one `forge-family` evidence group, not two independent confirmations.

## Confidence rules

External agreement is corroboration, not authority.

1. Primary MTG facts still come from the correct authoritative/structured sources and Ultimate MTG hard gates.
2. Related implementations are deduplicated by `independenceGroup` before confidence is increased.
3. A mismatch never automatically means Ultimate MTG is wrong; the external oracle, adapter, normalization, version pin, or Ultimate MTG may be wrong.
4. Every explained mismatch should become a regression fixture so the bug class stays fixed.
5. Live/network benchmarks remain separate from deterministic CI so third-party downtime cannot masquerade as a logic regression.
6. External versions must be pinned or recorded so changed upstream behavior is visible rather than silently altering expected results.
7. No target bracket, popularity score, one deck analyzer, or one external engine is allowed to override Commander legality, exact physical-printing requirements, or deterministic deck-construction rules.

## Planned benchmark phases

### Phase A — snapshot differential tests

Create normalized fixture cases for high-value behavior that can be reproduced without making CI depend on external availability.

Priority cases:

- exact card identity and legality;
- hypergeometric/package probability calculations;
- commander color identity and deck construction;
- mana-source probability calculations;
- common combat interactions;
- trample/deathtouch/first strike/double strike;
- ward/hexproof/targeting;
- replacement and prevention effects;
- triggered-ability ordering;
- stack/counter interactions;
- commander damage and commander-zone decisions;
- alternate/additional costs and cost reduction;
- Treasure/fast-mana sequencing;
- deterministic combo execution.

Each fixture records:

- case ID;
- Ultimate MTG model/version;
- external oracle ID and pinned version/commit;
- deterministic seed where applicable;
- scenario/input fingerprint;
- normalized external result;
- normalized Ultimate result;
- exact difference paths;
- resolution notes when disagreement is investigated.

### Phase B — optional live benchmark workflow

Run external projects or public interfaces in an opt-in GitHub Actions workflow. Failures caused by unavailable external services are reported as source-health problems, not core-regression failures.

A successful live run can refresh candidate snapshots, but snapshot changes must be reviewed before becoming deterministic expectations.

### Phase C — generated adversarial scenarios

Generate many legal bounded scenarios and compare families of outputs rather than only hand-picked examples.

Examples:

- randomized combat boards with keyword combinations;
- stack interactions with targeted/non-targeted effects;
- commander-zone replacement choices;
- combo lines with interruption windows;
- mulligan/draw/package probability cases;
- mana bases with changing color requirements;
- budget/theme/printing restrictions that pressure the optimizer into bad shortcuts.

Where possible, shrink a failing generated case to the smallest reproducible scenario before saving it as a regression fixture.

## What this does not do

- It does not declare Forge or another MCP universally correct.
- It does not import another project wholesale.
- It does not allow external agreement to certify Bracket 5 by itself.
- It does not merge GPL/AGPL source into the Ultimate MTG core merely because the code is public.
- It does not make deterministic CI depend on third-party network uptime.

## V0.15 implementation

`src/services/external-oracles-v15.ts` provides:

- a registry of initial external oracle projects;
- benchmark-domain mapping;
- licence/reference-use metadata;
- explicit lineage/independence groups;
- normalized snapshot comparison;
- precise mismatch paths;
- multi-source corroboration summaries that deduplicate related implementations.

The first unit suite proves, among other things, that Forge + Manabrew agreement is counted as one family while Forge-family + an independent MCP can provide two-source corroboration.
