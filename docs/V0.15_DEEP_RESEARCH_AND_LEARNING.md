# V0.15 Deep Research and Learning

V0.15 is an experimental layer on top of the current Commander/cEDH engine. It is deliberately not promoted to the stable runtime yet.

The goal is not to add a vague "AI score". The goal is to make MTG Ultimate better at separating strong evidence from repeated noise, learning from validated outcomes, and refusing to learn around hard Magic rules or physical-printing restrictions.

## Deep research

V0.15 treats different source classes as evidence for different questions.

- Official sources are strongest for rules and product facts.
- Scryfall remains the structured source for Oracle identity, legality and exact physical printings.
- Commander Spellbook remains the curated source for known combo structures.
- TopDeck.gg provides structured tournament outcome evidence when configured.
- EDHTop16 remains an attributed public competitive reference until a current stable structured API is independently verified.
- EDHREC, Archidekt, Moxfield and similar sources are useful for adoption, deck construction and primers, but popularity is not treated as proof of performance.
- Playgroup.gg can provide a different class of observed paper-game evidence.
- DeckCheck is an independent analysis opinion, not a ground-truth power oracle.
- TCGfind NZ and market sources answer availability/price questions rather than strategic optimality.

The research synthesizer scores observations using source weight, freshness, sample size, access mode and outcome strength. It also has an explicit `independentGroup` concept so two websites that ultimately repeat the same tournament, decklist or dataset are not counted as two independent confirmations.

Contradictory evidence is retained. Strong support and strong opposition can produce a `disputed` verdict rather than being averaged into false certainty.

Freshness is question-specific. Pricing and local availability decay quickly, tournament/metagame evidence decays faster than stable card identity, and official rules evidence decays slowly.

## Adaptive learning baseline

The first learning model is intentionally a transparent logistic ranker rather than a neural network.

It can learn weights for signals such as:

- simulation improvement,
- tournament support,
- cross-class research support,
- independently verified combo evidence,
- mana efficiency,
- interaction efficiency,
- price efficiency,
- community support.

A deterministic holdout split is required before learned weights are considered promotable. Small datasets or weak holdout accuracy block promotion.

This model is a baseline, not the final learning architecture. A more complex model should have to prove that it adds value over this transparent baseline on unseen data.

## Non-learnable hard gates

No learned model can override:

- Commander legality,
- exact 100-card validation,
- unresolved card/printing failures,
- exact physical-printing restrictions.

These are rule/data constraints, not preferences to be learned away.

## Deep-learning readiness gate

V0.15 includes a separate readiness evaluator before any neural "deep learning" model is treated as justified.

The default promotion bar requires, at minimum:

- enough labelled examples to make model complexity worthwhile,
- healthy positive/negative label balance,
- meaningful temporal coverage,
- multiple independent evidence groups,
- multiple evidence classes,
- low duplicate/dependent-data rate,
- passed leakage checks,
- a sizeable temporal holdout set,
- acceptable candidate accuracy,
- a material improvement over the transparent baseline on unseen temporal data.

The current defaults prefer at least 2,000 labelled examples for promotion, at least 200 temporal holdout examples, at least three independent evidence groups and three evidence classes, no more than a 10% duplicate rate, and at least a two-percentage-point gain over the transparent baseline.

A neural candidate that cannot beat the transparent model on unseen temporal data should not be promoted merely because it is more complex.

## Promotion strategy

V0.15 should remain experimental until deterministic CI, server-construction tests and live research smoke tests are clean.

A future neural model should first run in shadow mode: make recommendations without controlling production choices, compare its ranking against the transparent model and real outcomes, then promote only if it wins reliably without increasing rules/printing failures.

Stable runtime remains unchanged until that evidence exists.
