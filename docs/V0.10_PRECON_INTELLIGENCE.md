# V0.10 Commander Precon Intelligence

V0.10 makes Commander preconstructed decks a first-class part of MTG Ultimate.

The goal is not to freeze hundreds of decklists in source code. Instead, MTG Ultimate reads the current MTGJSON deck catalog, identifies Commander products, fetches the exact stock deck when needed, and then applies the same rules, printing, evidence and simulation engines used for user-built decks.

## Self-updating catalog

`list_commander_precons_v10` reads MTGJSON `DeckList.json`, filters Commander/EDH deck products, and caches the resulting catalog for a configurable period (six hours by default).

This means newly added Commander products can appear without publishing a new hard-coded catalog release. `forceRefresh` is available when an immediate refresh is wanted.

Catalog entries retain:

- product/deck name
- release date/year
- deck/set code
- MTGJSON file name
- product type
- product-variant identity

Regular, Collector/foil, or other distinct physical-product entries remain separate when the source lists them separately. This matters because the rules-equivalent deck can use different physical printings and therefore have different values.

## Exact stock deck identity

`get_precon_stock_deck_v10` fetches the individual MTGJSON deck record and creates a copyable stock decklist while retaining:

- quantity
- card name
- set code
- collector number
- foil/nonfoil status

Example format:

```text
// COMMANDER
1 Edgar Markov (C17) 36 *F*

// MAIN
1 Blood Artist (C17) 99 *N*
...
```

Oracle identity is still used for Magic rules and synergy. The stock physical printing remains separately identifiable for valuation and comparison.

## Stock analysis

`analyze_precon_v10` resolves the untouched deck through Scryfall and then runs:

- Commander legality / color-identity validation
- structural deck metrics
- theme hints
- Commander Spellbook bracket evidence
- known/near combo discovery
- the existing gameplay simulation

The normal response should stay simple: what the precon is trying to do, its biggest weaknesses, and the most useful upgrade direction.

## Upgrade profiles

`precon_upgrade_profiles_v10` exposes convenient starting points:

- **light** — up to 5 swaps; default $5/card cap; preserve the stock deck strongly
- **balanced** — up to 10 swaps; default $10/card cap
- **strong** — up to 15 swaps; default $20/card cap; target a strong Commander build while retaining the precon identity
- **optimized** — up to 15 swaps with no default per-card cap
- **custom** — explicit bracket, swap count, budget and other restrictions

These are defaults, not universal power guarantees. The caller can override bracket, price cap, swap count, theme, protected/excluded cards, set restrictions, and printing-family restrictions.

## Upgrade engine

`upgrade_precon_v10` always begins from the source stock deck. It then uses the existing upgrade engine to:

1. resolve and validate the stock list;
2. preserve the active commander/color identity;
3. identify structural deficits and weak candidates;
4. search for legal additions;
5. enforce exact printing/set/family and price restrictions;
6. create exact OUT -> IN swaps;
7. rebuild the complete Commander list;
8. validate it again;
9. simulate stock vs upgraded deck using the same seed;
10. return the full upgraded deck plus evidence.

This makes requests such as these first-class workflows:

- `Upgrade Vampiric Bloodlust, strong profile.`
- `Upgrade Endless Punishment, max $10 per card.`
- `Upgrade Limit Break but only use qualifying Final Fantasy printings including promos.`
- `Give this precon only five upgrades.`
- `Push this precon toward high Bracket 4 but keep these cards.`

## Upgrade evidence

Each precon response provides an EDHREC precon reference plus the wider V0.9 Commander research destinations.

EDHREC precon add/cut information is a community signal, not proof that the most-added card is automatically the best card. Upgrade decisions should also consider:

- the actual commander/game plan
- rules and color identity
- simulation deltas
- combos and interaction
- public/tournament references where relevant
- the user’s budget and desired power/bracket
- exact physical printing availability and price

## “All precons ever made” boundary

V0.10 means **all Commander/EDH preconstructed deck entries available in the current MTGJSON deck catalog**, not a manually asserted historical count baked into code.

This design is intentional: the source catalog can improve or add products without requiring MTG Ultimate to ship a new static database. If MTGJSON has a missing or incorrect historical product, the plugin should report the source limitation rather than invent a decklist.

## Future improvements

Useful next steps include:

- deeper structured ingestion of precon-specific community add/cut evidence where a stable source interface permits it;
- iterative upgrade optimization (generate several swap packages, simulate/cross-reference each, and keep improving until gains flatten);
- total-budget upgrade packs, not only per-card caps;
- precon-to-precon ranking by stock strength, upgrade ceiling, value and ease of upgrading;
- historical snapshots so “best upgrades at release” can be separated from “best upgrades today.”
