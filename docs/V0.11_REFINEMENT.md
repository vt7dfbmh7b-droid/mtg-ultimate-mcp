# V0.11 Refinement

V0.11 is primarily a quality and optimization pass. It does not replace the existing Commander rules, exact-printing, precon, evidence or simulation layers. It makes those layers work together more carefully.

## Main refinement loop

The new iterative optimizer uses this flow:

`legal starting deck -> propose small upgrade package -> rebuild full deck -> resolve exact cards/printings -> legality check -> same-seed before/after simulation -> budget check -> accept/reject -> repeat`

An accepted package becomes the starting point for the next round. Cards added in an accepted round are protected by default so the optimizer does not immediately remove its own successful changes. Cards cut in accepted rounds are excluded from being re-added during the same refinement run.

The optimizer stops when one of these conditions is reached:

- requested swap limit reached
- requested round limit reached
- no supported swaps remain
- all packages exceed the total budget
- a required printing has no verifiable price under a strict total budget
- candidate packages cause a significant simulated regression
- improvement falls below the requested threshold
- a rebuilt candidate fails card resolution or Commander legality

The optimizer should prefer returning the current legal deck over forcing a weak final round.

## New tools

### `refine_commander_deck_v11`
Iteratively refines any supplied legal Commander deck.

Key controls:

- target bracket
- maximum price per new card
- maximum total upgrade spend in USD reference pricing
- maximum swaps
- maximum rounds
- swaps per round
- minimum improvement score
- protected/excluded cards
- theme query
- allowed sets
- themed printing family
- promos/special-release inclusion
- simulation iterations/turns/seed
- simple/standard/detailed output

### `refine_precon_v11`
Starts from the exact MTGJSON stock precon and runs the same iterative loop. It includes convenient light, balanced, strong, optimized and custom starting profiles.

The exact stock list remains the baseline; a precon is not silently normalized or upgraded before comparison.

### `build_and_refine_commander_deck_v11`
Builds a legal first 100-card draft from one or two commanders, then iteratively refines that draft rather than treating the first generated list as final.

Must-include cards are protected during refinement. Theme, bracket and physical-printing restrictions stay active throughout both construction and refinement.

## Improvement scoring

V0.11 does not introduce a universal deck power score.

The internal acceptance score is only for comparing a candidate package with the immediately previous version of the same deck. It combines:

- functional opening-hand change
- commander uptime change
- protection success change
- average spells cast change
- smaller adjustments for interaction, protection, draw, ramp, tutor and early-play structure
- a small mana-value efficiency adjustment

Large regressions in keep rate, commander uptime or spell throughput can reject a package even if other metrics increase.

The score is an engineering heuristic. It is not a measured multiplayer win rate and should not be presented as one.

## Budget handling

`maxUsdPerCard` and `maxTotalUsd` answer different questions.

- `maxUsdPerCard` limits each selected incoming physical printing.
- `maxTotalUsd` limits the sum of the recommended printing prices across accepted refinement swaps.

When a strict total budget is supplied and an incoming printing has no usable reference price, the package is rejected instead of pretending the budget is satisfied.

For `build_and_refine_commander_deck_v11`, `maxPostDraftUpgradeUsd` only caps the refinement swaps after the initial generated draft. It must not be described as a full-deck purchase budget.

All pricing remains tied to exact physical printings, including set code, collector number and finish. Printing-family restrictions remain active.

## Simple output by default

Normal responses should return:

- whether refinement found an improvement
- why it stopped
- exact OUT -> IN swaps
- qualifying recommended printing and reference price
- estimated total upgrade spend
- final full decklist
- final Commander legality

Round-by-round scoring and raw simulation details are hidden unless `standard` or `detailed` output is requested.

## HTTP resilience

V0.11 adds bounded retry handling for safe GET/HEAD requests.

Retryable statuses:

- 408
- 425
- 429
- 500
- 502
- 503
- 504

`Retry-After` is honored when present, with bounded waits. Exponential fallback delays are used otherwise. POST/write-like requests are not automatically retried by the shared HTTP helper because they may not be idempotent.

Defaults:

- `HTTP_RETRY_ATTEMPTS=3`
- `HTTP_RETRY_BASE_MS=250`

This is intended to make MTGJSON/Scryfall/reference reads less fragile during temporary upstream throttling or outages without hiding permanent 4xx errors.

## Existing guarantees retained

V0.11 keeps the earlier guarantees:

- hard Commander color-identity and deck-construction rules
- exact Oracle identity vs physical-printing identity
- exact set code + collector number + finish-aware pricing
- themed printing families including qualifying promos/special releases
- self-updating Commander precon catalog
- known/near combo evidence
- bracket evidence
- multi-source deck/reference evidence
- hybrid gameplay/consistency simulation
- simple card explanations by default

## Boundaries

The iterative optimizer is intentionally conservative. It does not claim that a locally improved list is the globally strongest possible list, and it does not automatically sacrifice theme or desired win routes for a small simulation gain.

Simulation remains a model of selected game properties rather than a complete implementation of every Magic rule and multiplayer decision.
