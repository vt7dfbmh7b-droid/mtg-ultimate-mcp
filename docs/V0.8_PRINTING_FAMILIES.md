# V0.8 — Printing-family policies

V0.8 formalizes a distinction that matters for themed decks and real shopping:

- **Oracle identity** determines rules, legality, color identity, combos and card function.
- **Physical printing identity** determines whether an edition satisfies a requested theme/product restriction and which edition-level price applies.

## Example: “FINAL FANTASY printings only”

This is interpreted as a physical-printing policy, not as “only cards originally created for the main FINAL FANTASY set.”

A card can be used when it has at least one eligible physical printing tied to the requested family. The selected deck line must point at that qualifying printing.

Qualifying sources can include:

1. normal family-named sets
2. family Commander/supplemental sets
3. family promo sets
4. exact family bonus/special releases
5. exact franchise Secret Lair printings
6. exact bundle/product promos

`includePromos` defaults to `true` and `includeSpecialReleases` defaults to `true`. Both can be disabled explicitly.

## Safety rule: promo is not a family

A card is **not** eligible merely because Scryfall marks it `promo: true`.

Broad products such as Secret Lair contain many unrelated releases. A family policy therefore uses exact special-printing selectors for franchise drops that live inside such broad set codes. This prevents an unrelated SLD printing of a strong card from leaking into a FINAL FANTASY-only deck.

Conceptually:

```text
Oracle card: Cyclonic Rift

SLD 1869 — FINAL FANTASY themed -> allowed by FF family preset
other SLD printing             -> not allowed merely because set=SLD
ordinary printing              -> not allowed unless its own set belongs to the FF family
```

## Dynamic family-set discovery

The policy reads Scryfall set metadata and matches physical set names to the requested family. This means ordinary future family-named promo/supplemental sets can be discovered without hard-coding every set code.

Exceptional releases inside catch-all products still require exact selectors because the surrounding set code is not franchise-specific.

## Price behavior

A maximum price applies to the **qualifying physical printing**, not a random edition of the Oracle card.

Therefore:

- an expensive unrelated printing does not make a qualifying cheaper printing appear unaffordable;
- a cheap unrelated printing cannot satisfy a themed budget;
- foil/nonfoil/etched values remain printing-specific;
- the returned recommendation includes set code, collector number, finish, promo metadata and edition-level reference price.

## Builder behavior

`build_commander_deck_v08` applies the family policy to:

- commander printings
- every nonland card
- nonbasic lands
- basic lands
- must-include cards

If the requested family/price policy cannot supply enough cards to complete a valid 100-card list, the builder returns an incomplete draft. It does not fill missing slots with off-family editions.

## Upgrade behavior

`plan_commander_upgrade_v08` requires every suggested **IN** card to have an eligible physical printing. Existing off-family printings are reported separately by the printing audit.

`normalize_deck_printings_v08` can then attempt to convert each existing Oracle card to an eligible edition. If an Oracle card has no eligible edition, it is reported as unavailable and needs a card-choice replacement rather than an edition substitution.

## Direct family lookup

`find_printings_in_family_v08` answers questions such as:

```text
Which Cyclonic Rift printings count as FINAL FANTASY printings?
```

It returns only qualifying exact editions, making the family decision inspectable rather than hidden inside deck construction.

## Extensibility

The same system can support requests such as:

- Marvel printings only
- a specific Universes Beyond family
- cards from a named product family plus its promos
- explicit set-code-only decks
- family printings but no promos
- family printings excluding special releases

Future presets should prefer dynamic family-set discovery and use exact curated selectors only where a franchise release is embedded inside a broad catch-all product.
