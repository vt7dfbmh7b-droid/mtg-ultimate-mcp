## Cross-fixture diagnosis

The replay shows that `7b0e61d...` repaired **symmetry of exact requested-component comparison**, but not **reliable identification of those components on outgoing stock cards**.

The implementation currently builds `themeComponentCandidateNames` from bounded Scryfall searches and defines `componentAffinityForCard` by testing whether a card name appears in those returned name sets. This is appropriate as candidate discovery evidence, but it is too recall-sensitive to be the sole classifier for cards already present in the deck. A bounded search can omit a valid stock Aura, typal payoff, counters/explore piece, or commander-shape permanent even though the system has the full resolved card object in hand.

Repeated evidence across contrasting families therefore supports a new centralized defect:

**outgoing requested-component classification is search-result-membership dependent instead of directly evaluating the resolved outgoing card against the resolved component semantics.**

This explains why symmetric component scoring can be technically green while the failing precons remain strategically incoherent.

## Next justified product action

A further generic repair is justified because the same missing-classification pattern persists across enchantment/Aura, Merfolk/counters, Elf/typal-combat, and artifact/enchantment commander-shape fixtures.

The next smallest capability should:

1. separate *candidate discovery* from *component classification*;
2. keep bounded Scryfall searches for discovering incoming cards, but do not use returned-name membership as the sole truth for whether an already-resolved deck card belongs to a requested component;
3. classify outgoing cards directly from resolved card characteristics and the already-resolved component semantics wherever the query can be represented safely and generically;
4. preserve current fail-closed behavior for component semantics that cannot be evaluated locally rather than inventing card/commander exceptions;
5. feed direct component evidence into the existing advisory replacement identity comparator;
6. retain structural fallback when no credible on-plan alternative exists;
7. add focused regressions proving that cards outside a bounded search result can still be recognized as Aura/enchantment, typal, counters/explore-style, and artifact/enchantment/requested-shape components, while unrelated cards remain unclassified;
8. run full immutable validation, freeze the exact green source, and replay representative failures plus contrasting controls before acceptance.

Do not simply increase the search cap, freeze all theme cards, raise theme floors, add card-name exceptions, or make downstream component loss a hard veto. A larger cap may mask the recall problem without solving classification correctness.
